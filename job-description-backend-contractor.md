## The project

We are exploring a project to improve how our internal outreach platform receives, maintains, and uses healthcare facility and contact data. The goal is to reduce manual work and make the underlying records more reliable and useful. The work may involve data ingestion, data quality, enrichment, API integrations, or related backend improvements. We will define the specific scope, priorities, technical approach, and deliverables before entering into a project agreement.

This is a potential project opportunity. Any agreed project will have its own statement of work; later projects would be discussed separately.

## Possible areas of work

- Review current data workflows and recommend a practical improvement plan.
- Build or improve backend and data components that support approved sources and internal users.
- Test, document, and hand off agreed work so the team can operate and extend it.

These are examples, not a fixed deliverable list. The statement of work will specify the actual deliverables, milestones, acceptance criteria, and data-access boundaries before work begins.

## What you should be able to do

- Build maintainable Python services and data pipelines, including reliable API integrations.
- Work confidently with relational SQL, schema design, query performance, and data quality checks.
- Design idempotent imports, retries, error handling, logging, and tests for imperfect external data.
- Explain technical tradeoffs clearly and incorporate review feedback into a working solution.
- Handle sensitive business and personal information according to the agreed security and privacy requirements, including HIPAA.

## Selection process

Our planned process is demanding and aims to measure work relevant to this project. We will publish final instructions, time limits, permitted tools, accommodation options, and assessment data-handling details before candidates begin.

1. **Application and eligibility review:** Relevant work, basic project fit, and location/engagement eligibility; approximately 5–10 minutes to apply. 
2. **Practical reasoning (R1):** Approximately 45–60 minutes on logic, data interpretation, requirements, and concise communication.
3. **Technical assessment (R2):** Algorithmic coding (approximately 60–90 minutes) and applied computer fundamentals (approximately 45–60 minutes), scored separately.
4. **Mathematical problem solving (R3):** Approximately 60 minutes on unfamiliar quantitative and proof-oriented problems, with partial credit for sound progress.
5. **Role challenge (R4):** A 3–5 hour exercise using synthetic or isolated material, followed for qualifying candidates by blind rubric review, a 60–90 minute revision after feedback, and an approximately 60-minute structured discussion of their work.

[An optional preliminary general-aptitude screen (R0) may be used; if so, state its duration, monitoring rules, and place in the sequence before inviting applicants.] Candidates are evaluated against predefined standards across communication, reasoning, and engineering. Completing the process does not guarantee a contract.
