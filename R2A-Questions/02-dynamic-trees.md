# R2A: Dynamic Programming and Trees

## A06 — All Shortest Transformation Sequences

**Source:** Adapted from LeetCode 126, [Word Ladder II](https://leetcode.com/problems/word-ladder-ii/) (Hard). This is rewritten as an original assessment variant.

### Candidate prompt

Given `start`, `target`, and a set of equal-length lowercase tokens, one move changes exactly one character and the resulting token must be in the set. Return every shortest transformation sequence from `start` to `target`, including both endpoints. Return an empty collection if no sequence exists. Do not enumerate longer sequences. The dictionary may contain 50,000 tokens of length up to 10.

Example: with `start="cold"`, `target="warm"`, and an appropriate dictionary, both shortest valid chains must be returned rather than an arbitrary one.

### Proposed solution

Run breadth-first search by level to establish shortest distances. Maintain a predecessor set for each discovered token. When a neighbor is first found, record its distance and predecessor; when it is reached again at the same next-level distance, add the additional predecessor. Stop expanding only after completing the level that first reaches the target. Then backtrack from target to start through the predecessor DAG to enumerate sequences.

Neighbors can be generated by substituting each position with 25 alternatives, or through wildcard buckets. Complexity is proportional to explored neighbor generation plus output size; it cannot be stated solely as polynomial in dictionary size because the number of shortest sequences may itself be exponential.

### Key points and hidden cases

- A single `visited` predecessor loses valid shortest paths.
- Removing tokens after each BFS level prevents cycles without suppressing same-level parents.
- Test `start==target`, absent target, multiple parents, cycles, duplicate dictionary entries, and huge output.
- Candidate should mention output-size limits or streaming if the assessment environment needs protection.

| Preserves every predecessor at the shortest distance | 2 |
| Backtracks the predecessor DAG correctly | 2 |

## A07 — Restricted Pattern Matcher

**Source:** Adapted from LeetCode 10, [Regular Expression Matching](https://leetcode.com/problems/regular-expression-matching/) (Hard). This is rewritten as an original assessment variant.

### Candidate prompt

Implement full-string matching for a restricted pattern language. A lowercase literal matches itself, `?` matches any one character, and `*` means “zero or more occurrences of the immediately preceding atom.” The entire input must match the entire pattern. Patterns are guaranteed syntactically valid and never begin with `*`. Input and pattern lengths are at most 2,000.

Examples: `match("aab", "c*a*b")` is true; `match("ab", ".*")` would not be valid here because this variant uses `?`, so the equivalent pattern is `?*`.

### Proposed solution

Let `dp[i][j]` mean the first `i` input characters match the first `j` pattern characters. A literal or `?` uses `dp[i-1][j-1]` if the atom matches. When `pattern[j-1]=='*'`, either use zero copies via `dp[i][j-2]`, or—if the preceding atom matches `input[i-1]`—consume one more input character via `dp[i-1][j]`. Initialize `dp[0][0]` and allow empty input to match chains of starred atoms.

Time is `O(nm)`. Space may be `O(nm)` or reduced to `O(m)` with careful row handling.

### Key points and hidden cases

- Matching is anchored to the whole string, not substring search.
- Test empty input/pattern, zero repetitions, many repetitions, adjacent starred atoms, and long adversarial patterns.
- Naive recursive backtracking may be exponential; memoization is acceptable.
- The candidate must index the atom before `*` safely.

| Correct zero-copy and repeated-copy transitions | 3 |
| Correct literal/wildcard behavior and full anchoring | 2 |
| Polynomial complexity with valid bounds | 2 |
| Edge cases and clear tests | 1 |

## A08 — Minimum Edit Script

**Source:** Adapted from LeetCode 72, [Edit Distance](https://leetcode.com/problems/edit-distance/) (Hard). This is rewritten as an original assessment variant.

### Candidate prompt

Given two strings of Unicode code points, produce both the minimum number of unit-cost edits needed to convert `source` into `target` and one valid minimum edit script. Allowed operations are insert, delete, and replace one code point. If several scripts are optimal, prefer replace, then delete, then insert at the first differing decision. Each string may contain 5,000 code points.

### Proposed solution

Use dynamic programming where `dp[i][j]` is the minimum cost to convert the first `i` source symbols to the first `j` target symbols. Equal trailing symbols copy `dp[i-1][j-1]`; otherwise take one plus the minimum of replace, delete, and insert. Retain parent choices—or recompute them from a full cost table—then walk backward to construct the script, applying the specified tie order. Reverse the recovered operations before returning.

The straightforward solution is `O(nm)` time and `O(nm)` space. If only the distance were required, rows could be compressed to `O(min(n,m))`; returning a script generally needs parents or a divide-and-conquer reconstruction such as Hirschberg's technique.

### Key points and hidden cases

- Requiring the script prevents candidates from presenting only the familiar scalar distance.
- Test empty strings, equal strings, repeated symbols, supplementary Unicode, and tie cases.
- Operation positions must be defined consistently—prefer positions relative to the evolving string or explicit consumed prefixes.
- For 5,000×5,000, memory representation matters; compact integer/parent storage earns credit.

### Evaluation matrix (10 points)

| Evidence | Points |
| --- | ---: |
| Correct recurrence and initialization | 3 |
| Reconstructs a valid minimum script | 3 |
| Honors deterministic tie-breaking | 1 |
| Accurate complexity and memory discussion | 2 |
| Unicode/empty/tie tests and clarity | 1 |

## A09 — Binary-Tree Wire Codec

**Source:** Adapted from LeetCode 297, [Serialize and Deserialize Binary Tree](https://leetcode.com/problems/serialize-and-deserialize-binary-tree/) (Hard). This is rewritten as an original assessment variant.

### Candidate prompt

Design `encode(root) -> bytes` and `decode(bytes) -> root` for arbitrary binary trees whose node values are signed 32-bit integers. The encoding must preserve shape and values, support an empty tree, reject malformed or truncated data, and not depend on global state. State whether recursion is safe for a tree containing 200,000 nodes; if not, implement iteratively. Deterministic output is required.

### Proposed solution

One robust answer uses iterative preorder traversal with explicit null markers. Encode a tag byte for null/non-null and a fixed-width or length-prefixed integer for each non-null node. Decode with a stack of frames tracking whether each node next expects a left or right child. Consume exactly one root representation and reject trailing bytes, invalid tags, incomplete integers, or an unfinished frame stack.

An iterative breadth-first encoding with null markers is also valid. Text delimiters are acceptable if negative numbers, escaping, malformed tokens, and unambiguous boundaries are handled. Both directions are `O(n)` time and `O(h)` stack space for preorder, with encoded size `O(n)`.

### Key points and hidden cases

- Values alone cannot recover shape; null structure is essential.
- Test empty, one node, skewed depth 200,000, repeated values, integer extremes, truncation, illegal tags, and trailing garbage.
- Recursive code risks stack overflow on pathological trees.
- Security-minded candidates limit allocation and nesting based on input length.

| Handles pathological depth iteratively | 2 |

## A10 — Maximum-Gain Tree Path

**Source:** Adapted from LeetCode 124, [Binary Tree Maximum Path Sum](https://leetcode.com/problems/binary-tree-maximum-path-sum/) (Hard). This is rewritten as an original assessment variant.

### Candidate prompt

Each node in a binary tree carries a signed profit or loss. A route is a nonempty simple path following parent-child edges; it may begin and end anywhere but cannot revisit a node. Return the maximum route sum and the two endpoint node IDs of one optimal route. If several routes tie, any one is acceptable. The tree may be skewed and contain 200,000 nodes.

### Proposed solution

Postorder traversal computes, for each node, the best downward arm that starts at that node and chooses at most one child. Clamp a negative child contribution to zero. The best route whose highest point is the current node equals `value + max(0,leftArm) + max(0,rightArm)`; compare this with the global best. Store the endpoint associated with each chosen arm so the global update can retain both route endpoints. Return upward only one arm: `value + max(0,leftArm,rightArm)`.

Use an explicit stack with enter/exit states for the required depth. Time is `O(n)` and auxiliary space is `O(h)` plus stored per-node results if the traversal cannot mutate nodes.

### Key points and hidden cases

- The upward value cannot include both children; the global through-node candidate can.
- Initializing the global answer to zero is wrong for all-negative trees.
- Test one node, all negative, a best internal route excluding root, ties, and extreme sums.
- Endpoint tracking must match the selected arms, including the zero-arm case where the node is its own endpoint.

| Handles all-negative values and deep trees | 2 |
